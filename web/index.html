ここから始めれば進められます
この画面は、左を上から順に触っていけば、写真解析から確認、出力まで進められる作りです。 ただし写真解析は単体では動かず、裏でエージェント系の実行環境が動いている前提です。まずは「いま解析できる状態か」を見てから進めるのがコツです。
1

起動状態を確認する

最初に見るのは左下の「起動状態」です。`photo-ai.exe` や各 engine が揃っていても、それだけでは足りません。写真解析は AgentAPI 側の実行環境も使うので、Claude / Gemini などのエージェント系 CLI や常駐側が無いと、解析そのものが止まります。ここで missing や required が出ているなら、先にセットアップを済ませます。

ここでやるのは、写真解析の裏で使うエージェントAI実行環境のセットアップです。初回セットアップで一番迷いやすいのは、解析がアプリ単体で完結していないことです。まず Node.js / npm を使える状態にして、そのあと Gemini CLI を入れて認証します。Gemini を先に案内しているのは、最初に試す候補として分かりやすいからです。

もし `npm` 自体が無ければ、先に Node.js を入れます。やり方は環境ごとに違います。Windows はダウンロードページを開き、macOS / Ubuntu-Debian は下のボタンからコマンドを送れます。

npm install -g @google/gemini-cli gemini auth

認証まで通ったら、AgentAPI 側を起動してからこの画面に戻ります。詰まったら docs/QUICKSTART.md のトラブルシューティングを見れば、どこが欠けているか追えます。

2

工種を選ぶ

次に、左の工種マスタから今回の解析対象に近い工種を選びます。右上のマスタツリーは「その工種で何を拾う想定なのか」を見る場所です。解析結果がおかしい時は、まずここで選んだ工種が合っているかを疑うと早いです。

3

フォルダを指定

写真フォルダを選ぶか、パスを直接入力します。ここまで終わると Analyze を押せます。逆に言うと、工種とフォルダのどちらかが曖昧なままだと、その後の解析全体がずれやすいです。

4

解析する

Analyze を押すと、選んだ工種マスタと写真フォルダを前提に解析が走り、result.json が生成されます。ここで大事なのは「正しく選んだ前提で解析が進む」ことです。工種や写真区分に迷う時や、途中で止まる時は、右下ターミナルからエージェント側の状態を見ると切り分けしやすいです。

5

リザルトを確認する

解析直後の result.json は完成品ではなく、まず確認するための中間結果です。測点や備考が空欄のこともあるので、リザルトタブで未設定警告を見ます。手で直した同じ result.json を見直したい時は、ここからディスク再読込します。

6

問診票で整える

問診票タブは補正専用です。リザルトで不足や違和感を見つけたあとで、ここで測点や備考を整えます。未保存の編集がある時は、再読込しても黙って潰さないようにしてあります。

7

PDF / Excel を出力する

PDF / Excel は、いまこの画面で扱っている result.json からそのまま出ます。生成時に別のソースを選び直す作りではないので、確認と補正が終わってから出力するのが前提です。
